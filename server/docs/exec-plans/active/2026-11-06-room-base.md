# Room Base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every game a deterministic, replayable, observable multiplayer room built from a pure game definition, and prove it with the template game.

**Architecture:** Games write a browser-safe `GameDefinition` (state schema extending `BaseState`, zod input schema, `init`/`join`/`leave`/`step` and optional hooks). A pure `Simulation` in `@sdm/core/server` applies every event (join, leave, drop, reconnect, input, debug) and records it. The live Colyseus room and the headless `runReplay` both drive that same `Simulation`, so replays can't drift from live play. `@sdm/host` adds the HTTP routes, in-memory stores, pino logging and stats.

**Tech Stack:** TypeScript (ESM, `.ts` imports), Colyseus 0.18.11 (`setFixedTimestep`, `onDrop`/`onReconnect`/`allowReconnection`), `@colyseus/schema` 5.0.45 (`schema()` / `.extend()`), zod 4.6.7, Express 5, pino, Vitest, `@colyseus/testing`.

**Spec:** `server/docs/design-docs/room-base.md`. Read it first. This plan only adds the decisions the spec leaves open.

## Global Constraints

- Follow `CLAUDE.md` and `server/CLAUDE.md`: issue #12, one PR. The branch follows `platform/12-<short-description>`; confirm the exact name with the user before creating it. Commits are imperative, one logical change each, and carry `Refs #12` in the body. Commits and the PR carry no Claude/Anthropic attribution lines.
- Pinned versions, exact (no `^`): `pino` 10.4.0, `pino-pretty` 13.2.0, `@colyseus/monitor` 0.18.7 (all in `@sdm/host`), `@colyseus/testing` 0.18.6 (devDependency of `@sdm/template` and `@sdm/host`). Commit the lockfile.
- Browser-safe code (`@sdm/core/sim`, every game's `shared/`) imports only `@colyseus/schema`, `zod` and `@sdm/core/shared`. No `colyseus`, no `node:*`, no `@sdm/core/server`.
- Simulation code never reads `Math.random()`, `Date.now()` or `performance.now()`. Timing for stats is measured *around* `Simulation.tick()`, inside the room.
- Defaults: replay retention is the most recent 50 finished rooms or 1 hour; `MEMORY_BUDGET_MB` = 256; `REPLAY_MAX_EVENTS` = 1,000,000; bug report body ≤ 3 MB; bug report rate limit is 5 per minute per IP; stats interval is 10 s; `debug:stats` is sent every 1 s; the room code alphabet is `ABCDEFGHJKLMNPQRSTUVWXYZ`, 4 letters long.
- pino uses `messageKey: "message"` and string level names. It's pretty-printed only when `APP_ENV === "local"`.
- Contract changes (`server/core/src/shared/`) must be listed in the PR description as affecting no current games.
- Before each commit: `pnpm lint && pnpm typecheck && pnpm test`.

## Review Focus

1. **An input arrives while the room is paused.** It's counted as `inputsRejected.paused`, not queued, so a `step` after unpausing doesn't apply a burst of stale inputs. Test in Task 3.
2. **A player reconnects after their seat expired.** `client.reconnect` fails, and the template client falls back to joining the same code as a new player with a fresh seat. Test in Task 7 (expired seat → the reconnect is rejected and a new join succeeds).
3. **Joining a full room or an unknown code.** Both give a clear error the client can show, never a hang. Test in Task 6.
4. **A replay downloaded mid-game.** Re-running it to its `final.tick` gives the live room's hash at that tick. Test in Task 3 (`snapshot()` while running) and Task 7.
5. **A game's `step` throws.** The room logs at `error` with the replay URL, sends players a `Notice` and closes. The replay up to that tick is still downloadable, and the process stays up. Test in Task 6.

### Task 3: `Simulation`, state hash and replay runner

**Files:**
- Create: `server/core/src/server/simulation.ts`, `stateHash.ts`, `replayRunner.ts`, and their tests `simulation.test.ts`, `replayRunner.test.ts`
- Modify: `server/core/src/server/index.ts` (re-export)

**Interfaces:**
- Consumes: Task 1 (`Replay`, `ReplayEvent`) and Task 2 (`GameDefinition`, `SimContext`).
- Produces:
  - `stateHash(state: Schema): string`: SHA-256 hex (`node:crypto`) of `JSON.stringify` of `state.toJSON()` with object keys sorted recursively.
  - `class Simulation<S, I, C>`:
    - `constructor(def, opts: { seed: number; roomId: string; sha: string; scenario?: string | null; startedAt: string; config?: C; maxEvents?: number })`. `config` overrides `def.config`, which the replay runner needs.
    - `readonly state: S`, `readonly ctx: SimContext<S, C>`.
    - `join(playerId, rawOptions): void`. Parses with `joinOptionsSchema`, throws on invalid options, creates the `Seat`, calls `def.join`, and records `join` with the parsed options.
    - `leave(playerId)`, `drop(playerId)`, `reconnect(playerId)`. Each updates the seat, calls the matching hook if present, and records the event. `reconnect` also arms the seq reset.
    - `queueInput(playerId, envelope: unknown): InputResult`, where `InputResult = "ok" | "envelope" | "schema" | "stale-seq" | "paused" | "unknown-player"`. It never throws.
    - `tick(): void`. When paused, does nothing. Otherwise it: (1) drains queued inputs in arrival order, (2) records each as an `input` event at the current tick, (3) calls `def.step`, (4) sets each seat's `lastSeq` to the highest applied seq, and (5) increments `state.tick` and `ctx.tick`.
    - `applyDebug(playerId, command, args): string`. Records a `debug` event *before* running the command, then dispatches through Task 4's `runDebugCommand`.
    - `snapshot(): Replay`. Returns the replay so far, with `final = { tick, stateHash }`.
    - `readonly truncated: boolean`.
  - Every event is recorded with `tick = state.tick` at the moment it's applied. Joins, leaves, drops, reconnects and debug commands take effect immediately; inputs take effect at the next `tick()`.
  - Seq rule: an input is `stale-seq` if `seq <= lastQueuedSeq[player]`. After `reconnect`, the first input is accepted whatever its seq.
  - Past `maxEvents` (default 1,000,000), recording stops and `truncated` becomes true. The simulation keeps running.
  - `runReplay(def, replay, opts?: { untilTick?: number }): { state: S; tick: number; stateHash: string }`:
    - Throws `Error("replay is for game X")` if `replay.game !== def.id`.
    - Throws `Error("replay is truncated")` if `truncated`.
    - Otherwise builds `new Simulation(def, { seed, config: replay.config, ... })`. It walks the events in order, and before each event calls `tick()` until `state.tick === event.tick`. Input events go through `queueInput` with `{ seq, data }`.
    - It then ticks up to `final.tick` (or `untilTick`).

**Interfaces:**
- Consumes: Tasks 2–5.
- Produces:
  - `createGameRoom(def, deps: GameRoomDeps): RoomClass`, where `GameRoomDeps = { env: AppEnv; sha: string; stores: MemoryStores; logger; registry: LiveRoomRegistry }`.
  - `class LiveRoomRegistry`: `add(room)`, `remove(roomId)`, `byCode(code)`, `get(roomId)` (exposing `snapshot()`, `latestStats()`, `code`, `players`), `codes()` and `all()`. `@sdm/host` creates one per process and routes read from it.
  - `deps` reach the room through a factory closure. This task also changes `GameServerOptions.rooms` in `server/host/src/app.config.ts` to `Record<string, (deps: GameRoomDeps) => RoomClass>`. `createGameServer` builds one `MemoryStores`, one `LiveRoomRegistry` and the logger, calls `setLoggerGame(gameId)`, and passes the deps to each factory. Update the template's `room/index.ts` to the empty factory map so typecheck stays green.
- Lifecycle logs at `info`, through `roomLogger`: `room created`, `player joined`, `player left` (`{ consented }`), `player dropped`, `player reconnected`, `seat expired`, `player kicked`.
- Behaviour:
  - **onCreate(options):**
    - Seed with `newSeed()` and create the `Simulation`.
    - Set `maxClients = config.maxPlayers` and `patchRate = 1000 / config.patchRate`.
    - Call `setFixedTimestep(tickFn, config.tickRate)`.
    - If `options.private`, generate a code (checking taken codes through the registry), set `state.code`, and call `setMetadata({ code })` and `setPrivate(true)`.
    - Register in the registry, and start the 10 s stats interval and the 1 s `debug:stats` broadcast (debug envs only) using `this.clock`.
  - **tickFn:** measure `performance.now()` around `sim.tick()` and call `stats.recordTick(ms, late)`. A tick is late when the wall-clock gap since the previous tick is more than 2 × the interval. `timescale` is applied by skipping or doubling `sim.tick()` calls per callback *(builder's call)*.
  - **onJoin(client, options):** `sim.join(client.sessionId, options)`. Invalid options throw, so Colyseus rejects the join with the zod message.
  - **onMessage(input):** `stats.recordInput(sim.queueInput(sessionId, msg))`.
  - **onMessage(debug:command):**
    - Parse with `DebugCommandSchema`.
    - If `!isDebugEnabled(env)`, reply `{ ok: false, output: "debug commands are disabled in production" }` and log a `warn`.
    - Otherwise reply `{ ok: true, output }`, or `{ ok: false, output: err.message }` on error. Log every command at `info`.
    - `kick` also calls `client.leave()` on the target.
  - **onDrop:** `sim.drop`, then `allowReconnection(client, config.reconnectSeconds)`.
  - **onReconnect:** `sim.reconnect`, `stats.recordReconnect()`.
  - **onLeave:** `sim.leave` if the seat still exists. This covers consented leaves and expired seats.
  - **onUncaughtException:** log at `error` with `{ err, methodName, tick, replayUrl: Routes.replay(roomId) }`, broadcast `Notice { level: "error", text: "The room hit an error and closed." }`, then `disconnect()`.
  - **onDispose:** `stores.putReplay(roomId, sim.snapshot())`, unregister, and log `room closed` with `{ durationS, peakPlayers }`.
  - Every 10 s, log `room.stats` with `{ players, connected, ...stats.flush() }`.
  - Bytes out per patch: `onBeforePatch` can't see bytes, so `patches` counts calls and `bytesOut` is left at 0. Use a byte count if Colyseus 0.18 exposes one *(builder checks; documenting `bytesOut: 0` is acceptable)*.
